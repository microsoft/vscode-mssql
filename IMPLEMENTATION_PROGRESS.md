# SQL feature implementation progress

The implementation goal covers the complete table editor, DMV, Query Store, and SQL Server Agent plans. This file records partial progress; it is not a completion claim or a reduction in scope.

## Implemented foundations

- Created `packages/sql-feature` with explicit core, edit, DMV, Query Store, profiler, and Agent exports. Migrated extension imports and workspace dependencies. The superseded package directories still need final migration verification and removal.
- Fixed the malformed package ESLint configuration discovered in the existing worktree.
- Exact decimal/numeric encoding uses declared precision and scale with no floating-point intermediary. Rejects overflow and nonzero fractional digits that would be rounded. Money values use exact scaled-integer range checks.
- Column discovery resolves alias types through their base system type while retaining declared type/schema for presentation. Unknown types are no longer advertised as writable.
- Registered independent `mssql.sqlActivity.open`, `mssql.queryStore.open`, and `mssql.sqlAgent.open` commands and Object Explorer context actions. Query Store is connection/database scoped; Agent is connection scoped. The legacy Diagnostics command routes to Activity. The shared renderer no longer exposes cross-feature tabs, and backend query/action routing is scoped to its owning feature.
- Added connection/setup-settings entry actions, localized feature titles, session cleanup on discovery failure, and panel disposal on controller shutdown.
- Query execution now rejects completed-with-errors and contradictory success/error reports, preserves uncertain outcomes, and releases handles on rejected completion. Cleanup failure cannot relabel an acknowledged success. Streaming error completions are failures. Edit commits retain uncertain outcomes instead of claiming nothing was applied.
- Added Query Store readiness decoding and presentation: unsupported system databases, unknown/off/collecting/error/secondary states, requested versus actual read-only modes, combined reason flags, capture policy and storage. Historical readability is separate from collection. Unsupported/unknown/off states no longer render a generic empty result grid.
- Collection-mode changes now offer reviewed Apply (when configure permission is established) or Generate SQL, recheck configuration/access before applying, and verify actual state afterward. This is the initial setup operation, not the full settings wizard. Removed the incorrect claim that switching OFF discards history.
- Query Store readiness now offers a database picker using accessible online databases on the same connection. Selecting a database reuses host-held authentication and opens the appropriate database-scoped panel; cancellation leaves the original panel/session intact. Database-list failures are reported separately from empty lists.
- Added a Query Store settings dialog for operation mode, standard capture policies, aggregation/flush intervals, storage, retention, cleanup, and reported wait-capture support. Only changed fields are submitted. Domain SQL compilation validates enums, numeric values, supported intervals, identifiers, and SQL Server wait-capture version support. Review/apply now verifies each changed setting and prevents duplicate submissions; errors remain visible with the draft. Custom capture policy editing, presets, maintenance actions, detailed field validation/localization, and rendered/live-server verification remain outstanding.
- Corrected Query Store performance SQL: execution-weighted means, successful-execution defaults, query-level top consumers across plans, pooled duration variation including within/between-group variation, adjacent regression windows with a single time anchor, and plan counts instead of guessed previous-plan IDs. Window descriptions explicitly use aggregation-interval start assignment. Rich time/filter controls and coverage visualization are still pending.
- Replaced the shared diagnostic results table with `FluentSlickGrid`: virtualized compact rows, sorting, resizable columns, numeric alignment, theme support, and a row inspector for full returned statement text. Editor actions use the selected result snapshot and reject stale references in the host. Inspector text reports result truncation; complete-value fetching is still outstanding.
- DMV wait statistics now have a reversible background-wait filter, including internal dispatcher/Extended Events waits seen in the screenshots. The view explains cumulative scope and the filtered denominator; SQL preserves fractional average waits and exposes resource wait separately from signal wait. Row details provide conservative investigation guidance for common wait categories. Interval sampling and broader DMV readiness/overview work remain unfinished.
- DMV evidence snapshots now disclose the catalog's default row caps when callers do not provide an explicit limit, so capped workload results cannot appear unbounded. Denied collector states also offer a localized administrator-request clipboard handoff without treating unknown readiness as a permission failure.

- SQL Agent history/list durations now return milliseconds consistently with the grid format, widen arithmetic before multiplication, and retain valid midnight timestamps. A live SQL Server fixture covers one second, more than 24 hours, missing dates, and a duration beyond 32-bit milliseconds.
- SQL Agent job choices, scoped queries and mutations now use validated job IDs while displaying names. Selection updates and the dependent query run happen in one host reducer. Delete preserves schedules instead of implicitly deleting unused schedules. Full action review, permission checks, status verification and schedule management remain outstanding.

- Job creation now wraps the job, all steps, and server assignment in one transaction with explicit procedure return-code checks, rollback/rethrow, and a returned job ID after commit. It refuses an existing caller transaction. Validation rejects incomplete steps; the controller no longer silently removes blank commands or trims executable command text. Schedule creation, review/apply UI and full mutation outcome verification remain unfinished.

- Job creation now opens an exact-SQL review with Apply and Generate SQL choices. The host prevents concurrent creation submissions, returns per-creation status, and requires a returned job ID before reporting success. The dialog preserves its draft on cancellation, handoff and failure, disables editing during submission, and resets only after acknowledged creation. Dedicated review-flow/permission tests and richer administrator handoff remain outstanding.

- The creation form now supports adding, removing and reordering multiple T-SQL steps, with per-step name/database/command fields and explicit sequential success/failure behavior. All steps must be valid before review. Custom routing, retries and schedules are still outstanding; rendered interaction checks are pending.

- Creation supports per-step retry count and retry delay in minutes, carried through host validation into reviewed SQL. UI guidance explains repeated side effects and exhausted retries. Numeric validation rejects negative, fractional and out-of-range values. Custom success/failure routing and schedules remain unfinished.

- Added optional job-specific one-time, daily and weekly schedules to the creation form and domain batch. Date/time validation preserves server-local wall-clock values, checks calendar dates and date ranges, and compiles weekday masks/recurrence. Schedule creation participates in the job transaction with checked return codes. UI now defaults new jobs to disabled. Monthly/within-day recurrence, next-occurrence previews, shared schedules, and live Agent scheduling behavior remain unfinished.

- Added fixed day-of-month recurrence and within-day repeats in seconds/minutes/hours. The compiler checks monthly day range, minimum 10-second repeats, and ordered same-day time windows; switching to one-time removes hidden repeat options. Relative monthly rules, occurrence preview and DST verification remain outstanding.

- SQL Agent now checks service state separately from msdb role-based visibility and job-list readability. The readiness panel explains unsupported/stopped/unknown states, shows check errors separately, offers recheck and administrator guidance, and disables Run/Stop when the service is known stopped. Missing metadata and unrecognized roles remain unknown rather than becoming false denial/health claims. Fine-grained per-job action permissions and richer setup handoff remain outstanding.

- Agent Run/Stop/Enable/Disable/Delete now use reviewed Apply or Generate SQL, reject concurrent action submissions, and check stored-procedure return codes. Completion messages report request acceptance instead of job execution success. The Manage menu exposes enable/disable/delete; deletion review explicitly includes history deletion and schedule preservation. Refresh removes unavailable selection targets. Per-job permission preflight, definition-version checks and full outcome reconciliation remain unfinished.
- Agent creation now initializes each step from the selected connection database and requires an explicit database before review; an unknown connection database stays blank rather than silently targeting master. Host-side validation applies the same rule to untrusted webview payloads.
- Agent step database context is now required by the shared `sql-feature` creation API as well; omitted or blank direct requests are rejected before SQL generation. The standalone Agent page uses the selected connection database and leaves unknown context blank.

- Job actions now read current name, definition version, ownership, local/multiserver targeting, Agent roles and procedure permissions from msdb. Apply requires positive standard-role/ownership permission evidence; otherwise review offers administrator SQL handoff. The host rechecks the definition/access fingerprint immediately before execution and rejects drift. This does not yet make the precheck and mutation atomic, and custom-permission resolution plus post-action reconciliation remain outstanding.

- Job history now presents terminal execution summaries separately from retained step attempts, preserving retries and original row references for message inspection. Records without a trustworthy matching summary remain visible in an unassigned group; retention/row-limit uncertainty is explicit. Shared result grids now have unique instance IDs and optional selection callbacks so execution and step grids coexist. Complete-run pagination, richer failure evidence, timestamps/timezone handling and live history integration remain outstanding.

- Table editor drafts now retain their original row snapshots independently of the visible page. Unique-key drafts keep their row IDs across reloads; pending inserts remain visible across pages. Save builds all drafts, including off-page rows, and rejects missing snapshots instead of silently skipping edits. Draft mutations and navigation are blocked during the submitted save revision, copied values are committed, and stale page responses are ignored. This is in-panel retention, not disk persistence; ambiguous-key reconciliation, active-editor flushing and recovery UI remain outstanding.

- Large-value dialogs now expose loading, ready and failed states. Failed fetches never substitute the clipped grid value; editing is disabled until a successful retry. Closing or superseding a request ignores its late result. Document mutation controls also honor the save freeze. Successful-but-truncated data-plane responses still require completeness enforcement.
- Table editor page queries use one-row lookahead so exact full pages do not advertise a false next page; the normalized requested page size remains separate from the SQL fetch size. The `sql-feature` and superseded `sql-edit` engines are aligned.
