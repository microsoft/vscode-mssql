# SqlParser behavior-oracle gap map

This audit treats `C:\Users\aaskhan\src\SqlParser` as a behavioral reference, not as source to
port. SqlParser's functional tests keep parsing, error recovery, metadata binding, completion, and
quick info distinct. The portable fixtures in this directory retain those boundaries and use a
small synthetic closed-world catalog.

## Behavioral evidence audited

- Diagnostics and binding: `TestFiles/Input/InvalidObjectName/**`, the older consolidated
  `SkippedTestFiles/InvalidObjectName/**`, and `BinderTest.cs`.
- Recovery and edits: `ParserTest.cs` enables recovery by default; `CycleGuardTest.cs` exercises
  malformed trees and `Parser.IncrementalParse` without stack overflow.
- Hover/types: `Intellisense/Resolver.cs`, `SkippedTestFiles/Intellisense/UILevel1Verification/TooltipInfoUI.xml`,
  datatype inputs, and database-cache type definitions.
- Completion: `CompletionListTest.cs` plus `Intellisense/Level1Verification/CompletionListBVTTests/**`.
- DML/DDL: `TestFiles/Input/DML/**`, `createAndAlterTableTests/**`, and `DropStatementTests/**`.
- Batch/local state: table-variable binding tests, lexical-scoping inputs, temp-table DML cases, and
  GO-separated datatype/IntelliSense cases.

The SqlParser suite has much broader grammar/version coverage than these fixtures. That surface is
important, but it is secondary to the editor-semantic failures that motivated this audit. Expand the
portable oracle by behavior family and synthetic examples rather than bulk-copying XML variations.
